# Незавершённая интеграция аксессуаров — НЕ УСТАНАВЛИВАТЬ НА VDS

Это экспериментальные исходники, тесты и ресурсы, а не готовое обновление. Продакшен не менялся. Нет установщика и команды развёртывания. Бинарные заглушки в `stubs/` служат только тестированию и никогда не должны попадать в серверный JAR.

## Текущее поведение кандидата

- `accessories` / `аксессуары` — меню открывается всем; применение и отображение аксессуара требует `elytrixaccessories.admin`, default `op`.
- Спина: либо существующие крылья, либо щупальца; нимб независим. Выбор хранится в PDC игрока, при отзыве права отображение прекращается. Аксессуары чисто косметические и не используют слот брони. Старое автоматическое отображение от надетой брони удалено: его пользователю надо переоборудовать через меню; миграция предметов/данных не выполняется.
- Используется существующий `WornAngelRig` плагина 3.2.10, без переписывания геометрии и поворотной логики крыльев. Для нового вида скопированы параметры старого wing spec. Проверка в игре необходима: это не гарантия корректного расположения, анимации или отсутствия конфликтов.
- В `staging-assets` — только добавляемые ресурсы, сгенерированные из модели при `Use-New-Rotation=false` реальным ModelEngine 4.1.0 в среде с заглушками и fastutil 8.5.12, плюс вручную нарисованная иконка меню. Параметры namespace `modelengine`, texture path `entity/models`, как в Git-копии конфига. Live-конфиг может отличаться. Экспорт item JSON воспроизводит расположение и формат уже имеющихся ассетов. Визуальный рендер, корректность во всех клиентах и стабильность в игре не проверены.

## Изолированная проверка

`JAVA=/path/java ECJ=/path/ecj.jar python3 tools/accessories-integration/build.py /tmp/candidate.jar` выполняет mock-тест, патчит только плагин c SHA-256 `528956e976cbc4655bff35f97b2cef1b6f21ba63fbb4fa2953a21287b840ead6`, запускает ASM BasicVerifier и собирает кандидат в новый путь. `plugin.yml` получает команду и право. Файлы в `plugins/` не трогаются. Заглушки не включаются в кандидат. Для тестов используются ASM-классы из `plugins/BLib.jar`; ECJ и Java 21 подаются явно.

`python3 tools/accessories-integration/merge_staging_pack.py rp/Elytrix-RP-1.21.zip /tmp/candidate-rp.zip` создаёт **новый** тестовый ZIP, проверяет конфликты и атлас, сохраняет все существующие файлы и добавляет только 12 файлов. Это не синхронизация live ресурспаков и не обновление ElytrixRP SHA-1.

## До установки необходимо

1. На изолированном стенде с точными live-версиями Paper/DivineMC и ModelEngine проверить ABI, запуск/регистрацию blueprint и команд, миграцию от брони, выбор и сохранение при relog, отзыв прав, очистку сущностей, reload/restart, крылья/нимб и игровой рендер/движение в том числе в F5.
2. Проверить фактические `Use-New-Rotation`, namespace/texture path и все пути раздачи ресурспака; проверить, что ModelEngine создаёт идентичные item/model id. При несовпадении заново генерировать ассеты.
3. Разработать и протестировать инсталлятор с остановленным сервером, проверками версий и конфликтов, приватным бэкапом, rollback, атомарной синхронизацией обеих копий ресурспака и правильным SHA-1 ElytrixRP. Не трогать порт 8085, ModelEngine config/cache или данные игроков.
4. Другие запросы пользователя (DivineMC, KnockbackSync, сундуки, `/free`, кланы и остальные исправления) этим кандидатом не устанавливаются.

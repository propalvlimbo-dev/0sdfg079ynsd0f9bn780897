# Эксперимент с параметрами сервера

Установщик меняет только две настройки в существующих файлах:

* `start.sh`: `-Xms10G` → `-Xms8G`, `-Xmx10G` не меняется;
* `config/paper-global.yml`, `misc.compression-level`: `6` → `1`.

Архив не содержит live-конфигов или секретов. Установщик отказывается менять
файлы при неожиданных значениях и когда Java в рабочем каталоге сервера ещё
запущена. Он создаёт приватную резервную копию каждого изменённого файла в
`elytrix-config-backups/core-*`, проверяет синтаксис скрипта и не перезапускает
сервер. При ошибке в процессе замены пытается откатить изменения. Если параметры
уже установлены, повторный запуск ничего не меняет.

Менее сильное сжатие может снизить стоимость сжатия, но увеличить сетевой трафик;
его вклад в проблему не доказан. Более низкий начальный heap может освободить
память, но JVM вправе вырасти до 10 ГиБ, а поведение GC изменится. Влияет
только на запуск через изменённый `start.sh`. Это эксперимент, а не гарантия
20 TPS или исправления рывков. Дистанции, PvP, античиты, прокси, сохранения,
ограничители пакетов и защита от незагруженных чанков не изменяются.

Сохранённые файлы содержат настройки боевого сервера, в том числе возможные
секреты, и не должны публиковаться. Откат — вернуть нужные файлы из напечатанного
каталога резервной копии при остановленном сервере и затем запустить его заново.

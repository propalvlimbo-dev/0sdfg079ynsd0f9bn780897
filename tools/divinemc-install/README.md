# Elytrix: DivineMC 1.21.11 #30 — только ядро и стартовый конфиг

**Известная ошибка запуска:** оригинальный установщик не устраняет ранний `ClassCastException` пула чата в #30, даже при `virtual-threads.enabled: false`. Для эксперимента подготовлен отдельно `tools/divinemc-chat-fix/`; он не является официальным фиксом и не испытан на живом DivineMC. Не использовать старую core-only команду без учёта этой ошибки.

Установщик скачивает официальную сборку BX Team #30 и проверяет размер 68614411 байт и SHA-256 `505f6afd69ef2b555977dbfa7c37ea10988511531c8ca1bde1b35b88b3241f79` (официальные метаданные: https://api.bxteam.org/v1/builds/divinemc/1.21.11/30 ). Вендор помечает ветку 1.21.11 неподдерживаемой. Метаданные этой версии указывают Java 21+, а общая актуальная инструкция для новых версий — Java 25+; с конкретным JVM на VDS сборка нами не запускалась.

Устанавливать только при полном выключении сервера и автоматического перезапуска после свежего проверенного полного бэкапа, отдельно включая внешние базы. `/proc` проверяет часть работающих процессов, но не гарантирует обнаружение всех рестартеров, контейнеров и systemd units. Приложение вручную не останавливает процессы и не запускает сервер. Потребуются Python 3.9+, unzip и интернет на VDS. При уже существующем `divinemc.yml` скрипт не вносит изменения; нельзя удалять конфиг ради обхода проверки.

Создаётся новый `divinemc.yml`, остальные конфиги не перезаписываются. PWT, RCT, auto-thread-allocation, отключение проверок потоков, параллельный entity tracker, async mob spawning и async pathfinding выключены. Async chunk sending — включён, 1 поток. В конфиге виртуальные потоки выключены, но в этой сборке часть пулов создаётся до загрузки конфига — это значение не предотвращает ошибку пула чата. Создание снимков BlockState сохранено. Это консервативная стартовая конфигурация, не подтверждённая игровыми испытаниями и не обещание повышения FPS/TPS. Leaf/Gale/Paper/Purpur/spigot-настройки не переводятся автоматически: часть Leaf-настроек DivineMC не использует, а сам DivineMC при первом старте может дополнить или мигрировать свои и общие конфиги.

Существующий `server.jar` копируется в приватный `backup_dir/divinemc-core-*`; новый JAR предварительно проверяется SHA и ZIP, затем заменяется атомарно. Это **не полный серверный бэкап**: миры, внешние MySQL/другие БД и ресурспак нужно резервировать отдельно. При переключении между ядрами конфиги и миры могут измениться при старте; старый JAR сам по себе не гарантирует корректного отката.

Не устанавливаются KnockbackSync и другие плагины, не исправляются BCases/BLib и `/free`, `/eec`, косметика, ранее подготовленные кандидаты и т.д. Совместимость с плагинами и PvP не проверена. Установка тестирована локально с mock-файлами и подменённым скачиванием, не на настоящем DivineMC или VDS. Для выявления проблем сохранить полный лог первого запуска с удалением токенов/паролей перед отправкой.

Команда при выполненных условиях: `python3 install.py /root/RW_GRIEF /root/elytrix-backups --stopped --backed-up`

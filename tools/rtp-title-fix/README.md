# IRandomTeleport: кандидат исправления title (только staging)

IRandomTeleport 1.9 вызывает устаревшую NMS-рефлексию, которая использует четвёртый
компонент имени пакета CraftBukkit и на современных серверах вызывает
`ArrayIndexOutOfBoundsException`. Заменяется **только** тело статического метода
`ReflectionUtil.sendTitle(Player,String,String,int,int,int)` на стандартный
`Player.sendTitle(String,String,int,int,int)`. Остальные методы и ресурсы JAR
сохранены. Bukkit API поддерживает цветовые коды и null для заголовка/подзаголовка.
Это не подтверждает успешность телепортации или безопасность исходного плагина.

- Оригинал: SHA-256 `9a58cb93bc5916a8e3300dca41dec1df3e23b66fb4f2ae99d1e300749c524593`.
- Кандидат в архиве: SHA-256 `9d8eb64da2785657a13e14bd2c3d2086fca99eb3e304b40954337f3adf8a48dc`.
- Проверено: совпадение всех ZIP entries, кроме одного класса; mock-вызовы с
  проверкой текста, цвета, null и таймингов; `java -Xverify:all`.
- Не проверено: запуск на Leaf, реальный клиент, потоки событий плагина, вся
  логика телепортации, совместимость с боевой версией и конфигурацией.

Проверять только в изолированной копии при отключённом сервере-копии и после
консистентного бэкапа. Сначала сверить SHA оригинала на VDS: live может отличаться.
На копии сохранить оригинальный JAR вне папки plugins и заменить его кандидатом;
не оставлять оба JAR в plugins. Запустить копию в изолированной сети и без доступа
к боевым БД, протестировать обычный `/rtp`, `/rtp near`, таймеры, заголовки,
разные каналы, отклонённые телепорты, сообщения/ошибки, цены/кулдауны и игроков
с разными правами. Если тест не прошёл, остановить копию и восстановить оригинал.
Не использовать горячую перезагрузку плагина. Без реального теста это НЕ готовый
production-патч.

Для воспроизведения сборки нужен Java 17+, ECJ и локальный `plugins/BLib.jar`
как источник ASM. `JAVA=/path/to/java ECJ=/path/to/ecj.jar python3
 tools/rtp-title-fix/build.py /tmp/IRandomTeleport-staging.jar`. Выходной файл не
должен существовать, исходный JAR должен совпасть по SHA.

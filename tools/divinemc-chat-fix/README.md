# DivineMC #30: экспериментальный обход аварии пула чата

Причина: в исходниках DivineMC commit `e6d50f0aa6668e4917c653e6bfabcdd170b144ae` поле `MinecraftServer.chatExecutor` создаётся в конструкторе. `DivineConfig.init()` вызывается позднее, в `DedicatedServer.initServer()`. При этом ранний default `PerformanceCategory.virtualThreadsEnabled = true`, поэтому чат получает `ThreadPerTaskExecutor` ещё до чтения `divinemc.yml`. Paper `GlobalConfiguration.Misc.ChatThreads.postProcess()` безусловно приводит этот объект к `ThreadPoolExecutor` и падает. Изменение одного `divinemc.yml` не исправляет уже созданное поле. Это ошибка прежнего предположения установщика DivineMC.

Java-agent при загрузке ровно `DivineConfig$PerformanceCategory` меняет в `<clinit>` значение по умолчанию `virtualThreadsEnabled` с true на false, до конструирования сервера. Дальнейшее чтение конфига DivineMC не меняется. Это узкий неофициальный workaround, не исправление самого DivineMC, и действует только при запуске через изменённый `start.sh`. Он не редактирует серверный JAR, миры, плагины или конфиги. Нет реального теста на DivineMC #30/VDS: проверены воспроизведение исключения без агента, работа агента со стандартным и отдельным загрузчиком классов, `-Xverify:all` и mock-тесты установщика/отката. Требуется проверка лога запуска и плагинов.

Тестовый установщик работает только с оригинальным DivineMC 1.21.11 #30 SHA-256 `505f6afd69ef2b555977dbfa7c37ea10988511531c8ca1bde1b35b88b3241f79`, останавливается при неизвестном `start.sh` или активном процессе. Вносит один `-javaagent` в `start.sh`, сохраняет приватный бэкап и печатает команду отката. Перед установкой и откатом остановить сервер **и** цикл автоперезапуска, отдельно проверить консистентный бэкап. Не удалять распакованную во временный каталог папку, пока может понадобиться откат.

При запуске ожидаются две строки агента, вторая содержит `disabled virtual threads before server construction`; если её нет или повторяется `ClassCastException`, остановить сервер и прислать лог. Предупреждение `Invalid regionized chunk ticking thread count` отдельно от этого исключения; оно само по себе не причина падения.

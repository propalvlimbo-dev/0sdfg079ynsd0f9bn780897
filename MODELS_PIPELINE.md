# Как устроен конвейер моделей Elytrix — проверенная версия

Документ описывает то, что реально лежит в репозитории `propalvlimbo-dev/dfghjdyjk56`
и проверено по файлам, а не по памяти. Ниже — что подтвердилось, что оказалось
неточным и чего в старой формулировке не хватало (именно из-за этого 2 ноября
замена сороконожки не была видна в игре).

---

## 1. Модели (.bbmodel + текстуры + анимации)

### Среда
Blockbench в песочнице нет, нейросетевой арт запрещён. Модели и текстуры
генерируются процедурно: Python + `json` + Pillow, геометрия считается
тригонометрией и сразу пишется в `.bbmodel` (Blockbench 4.10, model_format `free`).

### Текстуры
Рисуются пиксельно через Pillow: градиенты, швы пластин, блики, шум.

Обязательный формат записи текстуры в `.bbmodel`:

```json
{
  "name": "elytrix_centipede.png",
  "width": 128, "height": 128,
  "uv_width": 16, "uv_height": 16,
  "internal": true,
  "source": "data:image/png;base64,..."
}
```

- `uv_width` / `uv_height` = **16** — это и есть сетка UV, в которой живёт
  геометрия. Не размер картинки.
- `width` / `height` — реальный размер PNG (может быть 64, 128, 256).
- `internal: true` — картинка вшита в `.bbmodel`, отдельный файл не нужен.

Проверено по всем блюпринтам: у `elytrix_angel_halo` PNG 64×64,
у `elytrix_angel_wings` 256×256, у остальных 64×64, и **у всех**
`uv_width/uv_height = 16`, `internal: true`.

### Главное правило UV (на нём 2 ноября всё и сломалось)

В файле модели UV задаются в диапазоне **0…16**, а не в пикселях текстуры:

```json
"faces": {"north": {"uv": [0, 0, 8, 4]}}
```

Эталон: у старой сороконожки 5 уникальных UV, максимум `16.0` при
`resolution 16×16`. Если записать UV в пикселях (`0…128` под текстуру 128 px),
модель сгенерируется, но текстура натянется с растяжением в 8 раз.

### Геометрия и кости
- Кубы в Minecraft JSON поворачиваются только по одной оси и шагом 22.5°
  (`-45, -22.5, 0, 22.5, 45`) — поэтому окружности (нимб) собираются
  из 16 сегментов и лучей под точными углами.
- Плавные 3D-повороты задаются на костях в секции `animations`: в игре
  ModelEngine превращает кость в отдельный `ItemDisplay`, который крутится
  кватернионами на любые углы.
- Иерархия костей важна: у крыльев обе половины в `right_wing_inner`
  / `left_wing_inner` с общим пивотом `[0.0, 20.4, 0.0]`; у Приоры
  `chassis / steering_wheel / steer_fl / steer_fr / wheel_fl / fr / rl / rr`;
  у сороконожки `body_root → c9 → c8 → … → c1` + `head`.

### Про `shade: false` и `scale = 2`
В **отгружаемом** паке этих значений нет:
- ключа `"shade"` в JSON модели нимба нет ни на одной из 480 граней;
- `"scale"` в паке встречается только у служебных моделей игрока
  (`models/custom/entities/player/*`), у крыльев его нет.

Что реально происходит — сжатие координат под `scaleToFit()`:
размах `right_wing_inner` в блюпринте `41.1` единицы, в JSON — `22.1`
(24.5 − 2.4), то есть координаты поделены на 2. Это подтверждает
`(coord - 8) / 2 + 8`, но сам множитель живёт в рантайме ModelEngine,
а не в JSON. Утверждение «ModelEngine ставит scale = 2» верно по смыслу,
но в файлах его искать не надо.

## 2. Экспорт в формат ресурспака

На каждую кость — два файла:

- `assets/modelengine/items/<модель>/<кость>.json` — описание предмета
  `minecraft:model` с `custom_model_data` tint;
- `assets/modelengine/models/<модель>/<кость>.json` — кубы кости,
  смещённые относительно её origin в центр `[8, 8, 8]`.

Причина: Minecraft обрезает кубы дальше 24 пикселей от центра `[-16…32]`.

## 3. Доставка на сервер: два разных файла, которые легко перепутать

Это место в старой формулировке было неполным, и из-за него 2 ноября
замена модели «не сработала».

| Что | Куда | Кто читает |
|---|---|---|
| `blueprints/<модель>.bbmodel` | `plugins/ModelEngine/blueprints/` | только ModelEngine (сервер) |
| сгенерированная папка `resource pack/` | `plugins/ModelEngine/resource pack/` | ModelEngine при `/meg reload` |
| **`/root/RP/Elytrix-RP-1.21.zip`** | раздаётся игрокам ElytrixRP | **клиент игрока** |

`ElytrixRP/config.yml` содержит `prefer-local-file: true`, то есть игрокам
уходит **готовый архив** с уже сгенерированной геометрией. Положив новый
`.bbmodel`, ты не меняешь ничего для клиента: в архиве остаётся старый JSON.

Проверка «дошло или нет» (до и после):

```bash
unzip -p /root/RP/Elytrix-RP-1.21.zip \
  assets/modelengine/models/elytrix_centipede/head.json | head -c 200
```

Правильная последовательность:

1. положить `.bbmodel` и PNG;
2. `meg reload` — ModelEngine перегенерирует `resource pack/`;
3. пересобрать `/root/RP/Elytrix-RP-1.21.zip`, заменив только файлы нужной модели;
4. записать новый `sha1` в `plugins/ElytrixRP/config.yml`;
5. `/elytrixrp reload` или перезапуск.

Шаги 3–4 автоматизирует `tools/centipede/centipede_apply.sh`:
он трогает только 22 файла сороконожки, остальные 3281 файл архива
(365 чужих моделей и их CMD) не меняет.

## 4. Сборка плагина

Исходники компилируются Eclipse `ecj` (`-21 -proc:none`) против реальных
`.jar` из `plugins/` (ModelEngine-4.1.0, BLib для JOML, FancyNpcs для Gson)
и упаковываются в `plugins/ElytrixFreakModel.jar`. Плагин находит кости
по именам (`c1…c9`, `head`, `root`) и анимирует их сам через
`ManualAnimator` / `crawlAngles`, поэтому при замене модели **имена костей
и пивоты менять нельзя** — иначе обход вокруг игрока отвалится.

## 5. Упаковка и загрузка

Архив собирается чистым (без `ModelEngine/config.yml`, без `.data/cache.json`
и чужих моделей MythicMobs), коммитится и пушится в рабочую ветку
репозитория `propalvlimbo-dev/0sdfg079ynsd0f9bn780897`. В ссылку
подставляется **полный 40-символьный SHA коммита**:

```
https://raw.githubusercontent.com/propalvlimbo-dev/0sdfg079ynsd0f9bn780897/<SHA>/<файл>.zip
```

По SHA GitHub отдаёт файл сразу, без кеша ветки. На VDS — одна команда
`curl && unzip && cp`, без порта `:8085`.

## 6. Чек-лист перед публикацией модели

- [ ] `meta.format_version` = `4.10`, `resolution` 16×16;
- [ ] у текстуры заданы `uv_width/uv_height = 16` и `internal: true`;
- [ ] **максимум UV = 16**, не в пикселях;
- [ ] имена костей и пивоты совпадают со старой моделью;
- [ ] прогнан рендер-превью и глазами проверены пропорции;
- [ ] после установки проверено `unzip -p .../head.json` — геометрия новая;
- [ ] `sha1` в `ElytrixRP/config.yml` совпадает с `sha1sum` архива.
